Scope

What this builds, and what it leaves alone

In
  • Save the current Leads filters under a name.
  • Pin, rename, reorder and delete your own saved filters.
  • Share a saved filter with your team (read-only for them).
Out
  • New filter fields or operators.
  • Saved filters on Opportunities or Accounts.
  • Email digests or alerts driven by a saved filter.
Whole system

A saved filter is a named query string

The Leads list already reads every filter from the URL. Saving stores that string; applying one navigates to it. The list endpoint is untouched.

Rules

  • Names are unique per owner, 1 to 40 characters.
  • A shared filter is read-only for everyone but its owner.
  • Editing the filters while a tab is selected shows “Update” next to Save.

Risks

What can go wrong, worst first

Must handle

Filter fields change

A stored query string can name a field that no longer exists. The validator runs on read as well as on write; see the open question for what the rep sees.

Must handle

Sharing shows more than intended

A shared filter shares the query, never the rows. Each viewer still gets only the leads their own permissions allow.

Noted

Name clashes with a team filter

Allowed. Team filters carry a “Team:” prefix in the tab.

Plan

Two phases, each shippable

Phase 1

Private saved filters

  • Table, four endpoints, validator.
  • Tab row, save dialog, rename and delete.

A rep saves a filter, reloads, taps its tab and sees the same leads. Deleting a filter field from the schema does not break the list.

Phase 2

Team sharing and pin order

  • Share toggle, “Team:” tabs, drag to reorder.

A teammate sees a shared filter as a read-only tab and gets only their own leads through it.
